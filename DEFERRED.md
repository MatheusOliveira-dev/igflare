# Deferred

Work intentionally postponed. Each item names the trigger that should bring it back.
Read this file before `npm publish` or cutting a release tag.

| Item                                                                                                                                                                                                                                                               | Trigger                                                             |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------- |
| npm publish provenance (`--provenance` in the release workflow; the release script refuses to publish without it)                                                                                                                                                  | First publish                                                       |
| Typedoc + a check that public API has doc comments                                                                                                                                                                                                                 | First stable release tag (`v*`)                                     |
| Mutation testing wired into CI as a gate                                                                                                                                                                                                                           | When the critical modules are large enough to warrant the CI time   |
| Contributor setup: `CONTRIBUTING.md`, PR/issue templates, "good first issue" labels                                                                                                                                                                                | First external contributor                                          |
| Branch protection on `main` and CODEOWNERS enforcement                                                                                                                                                                                                             | When the repo is pushed to GitHub                                   |
| Extra `SessionStore` adapters (Mongo, Redis, encrypted-at-rest, multi-account), as optional or separate packages so the core stays dependency-free                                                                                                                 | When a provider is requested                                        |
| Captured real-Bloks login response as a golden fixture (the current CAA tests use synthetic vectors, so a subtle shape drift in a real response could pass). Requires a sanitized capture of a real `send_login_request` response                                  | When a real login response can be captured                          |
| Name the public facade class and the npm package (a memorable brand, not `instagram`/`ig`; a scoped package eases availability). The name touches only the facade and `package.json`, so it stays cheap to change until published                                  | Before the facade lands or the first publish, whichever comes first |
| Capture `Set-Cookie` from ordinary responses into the session. Needs the transport to expose repeated `Set-Cookie` as an array (Node collapses them into one comma-joined string, which corrupts cookie dates); the auth cookie already arrives via the CAA bundle | When an endpoint needs a cookie that only a non-CAA response sets   |

These are config/docs with no retrofit cost, which is why they can wait. The expensive
guards (types, tests, generation, boundaries) are already in place.
